**Status**: Draft

**Target Launch**: Q2 2026

## 1. Product Overview & Strategic Goals

PetCare AI is a transparency platform that empowers pet owners to validate veterinary costs using crowdsourced regional data. The MVP aims to prove that AI can accurately categorize fragmented vet billing data and provide a "Fair Market Value" (FMV) verdict.

### User Personas

- **The Anxious Owner**: Just left the vet with a $1,200 bill; needs immediate validation before paying or for future visits.
- **The Budgeter**: Wants to pre-shop "big ticket" items like dentals or ACL surgery.
- **The Contributor**: Motivated by community; uploads receipts to help others avoid gouging.

### Success Metrics (KPIs)

- **Extraction Accuracy**: >90% correct mapping of line items to standardized categories.
- **Database Growth**: Number of unique zip codes with at least 5 data points.
- **Conversion**: % of free users who scan a second bill (indicating trust in the first verdict).

## 2. Functional Requirements (The "Three Parts")

### Part A: The AI Extraction Engine (Input)

The system must transform a physical artifact (receipt) into structured data.

- **Multi-Modal Upload**: Support for .jpg, .png, and .pdf.
- **OCR & Entity Mapping**:
  - Extract: Clinic Name, Zip Code, Date of Service, Species, and Weight (if available).
- **Line Item Extraction**: Capture Description, Unit Price, and Quantity.
- **Normalization Layer**: Use an LLM to map "fuzzy" text (e.g., "DHPP 1yr") to a master procedure list ("Distemper/Parvovirus Vaccine").
- **Anomaly Flagging**: Identify items that aren't medical (e.g., "Leash," "Boarding") and exclude them from the medical FMV calculation.

### Part B: The Regional Pricing Engine (Logic)

The core "Verdicts" are generated by comparing extracted data against the Supabase backend.

- **Geospatial Lookups**:
  - Primary match: 5-digit Zip.
  - Fallback 1: 3-digit Zip prefix (Regional).
  - Fallback 2: State-wide median.
- **The Verdict Algorithm**:
  - **Green (Fair)**: Within 1 standard deviation of the median.
  - **Yellow (High)**: 1–2 standard deviations above.
  - **Red (Outlier)**: >2 standard deviations above or >40% above the 90th percentile.
- **Species Logic**: Weight-based adjustment for medications and anesthesia (e.g., a 100lb dog's sedative vs. a 10lb cat's).

### Part C: The Transparency UI (Output)

A mobile-first dashboard that delivers "Clarity in under a minute."

- **The Verdict Header**: A clear, color-coded status (e.g., "Total is 12% lower than the Austin average").
- **Line-Item Breakdown**: A list view where clicking a high-cost item shows a Beeswarm Plot or Bell Curve of regional prices for that specific service.
- **Actionable Next Steps**: If a bill is "Red," provide a "Negotiation Script" or a link to the nearest clinic with a "Green" rating for that procedure.

## 3. Technical Requirements & MVP Schema

### The Data Model (Supabase/Postgres)

To handle the geospatial and relational needs:

```sql
-- Core Table for Regional Pricing
CREATE TABLE procedure_benchmarks (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
  procedure_key VARCHAR NOT NULL, -- e.g., 'dental_cleaning_level_1'
  zip_code VARCHAR(5),
  location GEOGRAPHY(POINT),     -- For PostGIS radius searches
  median_price DECIMAL,
  p90_price DECIMAL,
  sample_size INTEGER,
  species VARCHAR(20)            -- 'dog' | 'cat'
);

-- User Uploads for the Flywheel
CREATE TABLE user_receipts (
  id uuid PRIMARY KEY,
  user_id uuid REFERENCES auth.users,
  clinic_name TEXT,
  total_amount DECIMAL,
  raw_json JSONB,                -- Store full OCR output for retraining
  is_verified BOOLEAN DEFAULT false
);
```

### MVP Constraints & Phasing

- **Phase 1 (Seed)**: Manual import of public pricing from 10 major US cities.
- **Phase 2 (Alpha)**: Reddit-based "First 500" users (Manual verification of "Red" flags by the 3 contracted vet techs).
- **Phase 3 (Beta)**: Automated regional averaging and Stripe integration for unlimited scans.
